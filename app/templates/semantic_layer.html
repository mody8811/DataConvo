What a semantic layer is supposed to do

A semantic layer is the governed definition of your business that sits between the warehouse and everyone querying it. The hard part was never the concept. It was keeping the definitions current without a codebase to babysit.

Manual dbt / YAML

  • Every metric lives in .yml files across a repository
  • A change needs a branch, a review, and a CI run before it is live
  • Joins are declared in code, disconnected from the schema they describe
  • Access rules are bolted on afterwards, in a different system
  • Nobody outside the data team can read or verify the model

Data Convo

  • Definitions live in one JSON model attached to the live connection
  • Edit in the browser and publish: no branch, no build, no deploy
  • Joins are drawn on an ERD canvas against real PK/FK constraints
  • Table and column permissions are enforced before SQL is generated
  • Business definitions are written in plain language your team can audit

Three studios, one governed model

The semantic layer is the foundation. Each studio is a different way to use it, and they run against the same definitions so answers stay consistent across all three.

01

Semantic Studio

Introspect your warehouse, then model it visually. Drag columns to link tables on an ERD canvas, and define aliases, synonyms, enums, custom metrics and business definitions in plain language.

  • ERD join modeling with FK constraints
  • Custom metrics and named business definitions
  • Column aliases, enums and synonym maps
  • BYOK: your OpenAI, Anthropic or OpenRouter key
  • Table and column level security per member
The model every studio reads from
02

Anomaly Studio

The semantic layer tells you what the data means. Anomaly Studio tells you when it stops meaning that. Baseline each monitored column, then get alerted the moment the shape of the data changes.

  • Per-column baselines: distribution, volume, type
  • Deviation flagged at roughly three sigma
  • Null spikes and volume shifts detected automatically
  • Alerts routed to email or a Slack webhook
  • Status and history on the dashboard
Catches broken pipelines before the dashboard lies
03

Interactive Dashboarding Studio

Ask a question, get a chart, then keep talking to it. Results render as charts and KPI cards, and follow-up questions run against the same dataset, so refining a view never means going back to SQL.

  • Natural-language questions over the semantic model
  • Charts and KPI cards generated from the result set
  • Chat directly about the visual on screen
  • Pivot, filter and drill without writing SQL
  • Self-healing SQL that corrects on error
Chat with the chart, not just the database

From warehouse to answered question

  1. Connect

  2. Profile

  3. Define

    Draw joins, then add aliases, enums, metrics and business definitions in business language.

  4. Publish

    The model is persisted and injected into every prompt. Ask a question, get a chart, keep chatting.
